# 避免不必要的函式間耦合（redundant cross-function coupling）

不要為了驗證某個操作的結果，而去呼叫另一個函式重新確認 —— 當這個操作本身「成功就是成功，失敗就會丟例外」，中間沒有靜默失敗的可能時，這個驗證是多餘的。

## 案例

`create_database` 原本這樣寫：

```python
def create_database(database_path: str) -> bool:
    Path(database_path).parent.mkdir(parents=True, exist_ok=True)
    con = db.connect(database_path)
    con.close()
    return is_file_exist(database_path)
```

`duckdb.connect(...)` 要嘛成功建立檔案，要嘛直接丟例外，執行到 `return` 這行就已經證明檔案存在了，再呼叫 `is_file_exist` 重新檢查一次沒有意義。

修正後：

```python
def create_database(database_path: str) -> bool:
    Path(database_path).parent.mkdir(parents=True, exist_ok=True)
    con = db.connect(database_path)
    con.close()
    return True
```

## 為什麼在意

這種寫法會讓兩個原本該獨立的函式產生隱性耦合：如果 `is_file_exist` 本身有 bug，`create_database` 的回傳值會被連帶拖累出錯，即使 `create_database` 自己的邏輯完全正確。之後排查問題時，也會先懷疑錯的那個函式，增加除錯難度。

## 怎麼判斷

寫函式時問自己：「這一行程式碼有沒有可能在失敗/錯誤狀態下被執行到，還是前面那行已經用例外排除掉這個可能？」
- 有可能 → 才需要額外檢查
- 前面已經排除 → 直接回傳已知值，不用再呼叫別的函式確認
